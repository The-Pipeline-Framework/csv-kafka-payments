# CSV SQS payment provider Lambda

This is a standalone Java Lambda package for the existing CSV Payments SQS Await request queue. It receives a finite SQS event batch, applies the existing deterministic payment mock, and sends the existing Await completion envelope to the response queue. It returns each failed request message ID in `batchItemFailures`; successful records are acknowledged only after the completion send succeeds. A missing message ID fails the invocation before that record has a side effect. It does not delete request messages or run a resident queue poller.

Build with `./build-provider-lambda.sh` from the repository root. The script first builds the SQS FUNCTION/REST `common` and `payments-processing-svc` artifacts and runs `PaymentProviderSqsAwaitMockTest`, then builds and tests this standalone child. Pass the approved `-Dpipelineframework.bom.version=...` coordinate used for the rest of the application. The child is intentionally absent from the default parent reactor so COMPUTE/GRPC builds remain unchanged. The deployable Java artifact is `provider-lambda-svc/target/function.zip`; the AWS Java handler is `io.quarkus.amazon.lambda.runtime.QuarkusStreamHandler::handleRequest`, with `quarkus.lambda.handler=csv-provider` selecting this raw SQS handler. The current diagnostic ZIP is 102 MiB compressed, above Lambda's 50 MiB direct-upload limit, so a same-region S3 code artifact is required for this ZIP form. Set `CSV_PAYMENTS_PAYMENT_PROVIDER_SQS_RESPONSE_QUEUE_URL` for the response queue. The package disables the inherited SQS and Kafka provider beans, Kafka channels, HTTP/gRPC listeners, and default OTLP export. When an OTLP endpoint is supplied, `QUARKUS_OTEL_SDK_DISABLED=false` may enable telemetry export.

The SQS event source mapping must enable **ReportBatchItemFailures**. Set a bounded batch size and maximum concurrency, a Lambda timeout long enough for the provider call and response send, a queue visibility timeout longer than the Lambda timeout plus retry margin, and a dead-letter queue with an explicit receive limit. The request and response queues need corresponding IAM receive/send permissions. Lambda redelivery can repeat the deterministic mock and completion send; the completion uses the stable interaction ID as idempotency key, but this does not guarantee exactly-once provider side effects.

The two accepted Await wire pairs are the existing nested protobuf `PaymentRecord`/`PaymentStatus` identities and generated FUNCTION/REST `PaymentRecordDto`/`PaymentStatusDto` identities. Unknown pairs fail their record. No pipeline YAML or business outcome semantics change here. This module and its local tests do not establish full Hosted pilot acceptance, durable Await recovery, object ingestion, or a matching framework release cohort.
